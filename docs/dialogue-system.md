# ウサちゃんロボ 対話システム設計

最終更新: 2026-08-20

## 前提（確定事項）

| 項目 | 決定 |
|---|---|
| ハード | M5Stack CoreS3 |
| 可動 | なし（画面と音のみ）。可動は将来フェーズ |
| 構成 | PC母艦。重い処理は PC、CoreS3 は顔表示・音声出力・センサ |
| ゴール | 原作再現（池袋晶葉のウサちゃんロボ） |

### 実行環境
- CPU: AMD Ryzen 7 7435HS (8C/16T) / RAM 16GB
- GPU: RTX 3050 Laptop **VRAM 4GB**
- Python 3.12.10, Node.js あり
- 導入済: Ollama / Python 依存パッケージ
- 未導入: VOICEVOX, PlatformIO

VRAM 4GB は **LLM が最優先で使う**。STT と TTS は CPU に回す。
LLM がレイテンシの支配項なので、ここに GPU を明け渡すのが正しい配分。

## 中核となる設計判断

### 1. レイテンシ：文単位ストリーミングパイプライン

対話ロボットの成否は応答内容より「間」で決まる。素朴な直列実装は壊滅する。

| 実装 | 初音出しまで |
|---|---|
| 直列（STT完了→LLM全文→TTS全文→再生） | 5〜8秒 |
| **文単位ストリーミング（設計目標）** | **1.6〜2.6秒** |

#### 実測値（2026-08-20 / qwen3:4b-instruct / num_ctx=2048）

| 区間 | 実測 |
|---|---|
| LLM 初トークン | **0.68s** |
| LLM 第1文が揃うまで | **0.89〜1.22s** |
| LLM 応答全体 | 1.3〜2.1s |
| モデル初回ロード（コールドスタート） | 約6.5s（2回目以降は発生しない） |

VAD 終端検出（0.3〜0.5s）+ STT（0.2〜0.4s）+ 上記 + TTS（0.2〜0.4s）で、
**初音出しは 1.6〜2.0s 程度の見込み。設計目標の範囲に収まっている。**
（TTS は VOICEVOX 導入後に実測して確定させる）

内訳:

| 段 | 所要 |
|---|---|
| VAD 終端検出（hangover） | 300–500ms |
| STT tiny（ウェイク判定） | 50–100ms |
| STT small（本命・3秒発話） | 200–400ms |
| Claude 初トークン | 600–900ms |
| 第1文が揃うまで | +200–500ms |
| VOICEVOX 1文合成（CPU） | 200–400ms |
| Wi-Fi 転送 + プリバッファ | 100–150ms |

**肝は LLM 出力を句点で切って 1 文ずつ TTS に流し、再生キューに積むこと。全文を待たない。**

### 2. ウェイクワード：VAD + whisper tiny による判定

専用ウェイクワードモデル（openWakeWord / Porcupine）は使わず、まず以下で始める:

1. Silero VAD が発話区間を切り出す（無音時は何も走らない）
2. faster-whisper **tiny** で高速に文字起こし（50–100ms）
3. 「ウサちゃん」「うさちゃん」等を部分一致で判定
4. ヒットしたら faster-whisper **small** で同じ音声を再認識（本命の精度）

利点:
- 追加のモデル学習が不要。日本語がそのまま動く
- ウェイクワードの変更が設定ファイルの文字列1行
- VAD がゲートするので常時 GPU を回さない

**一発発話に対応する**: 「ウサちゃん、今日の天気は？」のように 1 発話にウェイクワードと用件が両方入る場合、ウェイクワードを除いた残りが空でなければそれを即クエリとして扱う。空なら「呼ばれた」反応を返して 5 秒の会話ウィンドウを開く。

**会話モード**: 一度起動したら N 秒（初期値 20 秒）はウェイクワード不要。毎回名前を呼ばせるのは相棒感を殺す。

誤受理が実用上問題になったら openWakeWord のカスタムモデルに差し替える（インターフェースは `wake.py` に閉じる）。

### 3. 待ち時間は演出で埋める

1.6 秒はまだ「間」が空く。技術で消せない分は CoreS3 の顔で埋める。

状態機械 `idle / listening / thinking / speaking` を PC 側で持ち、遷移のたびに CoreS3 へ push する。**耳がぴくっと動く・目が上を向いて考える**——この 0.5 秒が入るだけで、待ち時間が「無視」から「反応」に変わる。可動を捨てた構成だからこそ画面の演出が効く。

### 4. barge-in と音響エコー

喋っている最中に話しかけられたら即座に黙る。生き物っぽさが段違いに変わる。

実装自体は単純（PC 側 VAD が発話を検出 → TTS キュー破棄 + CoreS3 へ `audio_flush`）。
**難しいのは音響エコーのほう。**

マイクとスピーカーが同じ空間にある以上、ウサギの声を自分のマイクが拾う。
素朴に barge-in を有効にすると、**自分の声に自分で割り込んで即座に黙る**。

| 構成 | エコー経路 | 対策 |
|---|---|---|
| Step 1（PC マイク + PC スピーカー） | 至近距離。最悪 | 再生中はマイクを閉じる（barge-in 無効） |
| 最終形（PC マイク + CoreS3 スピーカー） | 部屋を挟むが依然あり | AEC が要る |

**Step 1 では `behavior.barge_in: false` とし、再生中はマイクを閉じている。**
再生終了後にマイクの滞留フレームを捨てて VAD をリセットしてから待受に戻る
（これをやらないと、自分の声の残りを次の発話として拾う）。

有効化は Step 5。AEC を入れるか、「現在読み上げ中のテキストと一致する認識結果は無視する」
という簡易フィルタで妥協するかは、そのとき実測して決める。

**CoreS3 のバッファ長は barge-in の応答性と Wi-Fi ジッタ耐性のトレードオフ。300ms を初期値とする。**
長くすると途切れにくいが、割り込んでから黙るまでが鈍くなる。

> barge-in は「喋りながら聞く」＝全二重を要求する。CoreS3 の内蔵マイクとスピーカーは
> I2S を共有していて同時使用に制約があるため、**入力を PC 側に置いた本構成は
> この問題を構造的に回避している。**

### 5. 感情表現：インラインタグ

LLM に `[喜]` `[困]` `[驚]` のようなタグを本文中に吐かせ、TTS に渡す前に剥がして表情 state に変換する。

JSON 構造化出力は使わない——ストリーミングが崩れて文単位パイプラインが死ぬ。

### 6. LLM はローカルで動かす（Ollama）

クラウド API を使わないので**課金はゼロ**、レート制限もなく、ネット接続も不要。
PC さえ動いていればウサギは喋る。

`llm/client.py` は Ollama と Claude API を同じインターフェースで扱う。
`config.yaml` の `llm.backend` を `claude` にすれば差し替わる（要 `ANTHROPIC_API_KEY`）。
その場合はペルソナを system に置いて prompt caching を効かせ、`effort: low` で使う。

#### モデル選定で判明したこと（重要）

**推論（thinking）モデルは対話ロボットに使えない。**

最初 `qwen3:4b` で試したところ、以下の挙動になった:

| 設定 | 結果 |
|---|---|
| `think` 指定なし | 思考が `message.thinking` に分離される。ただし本文が出るまで10秒以上かかる |
| `think: false` | 思考が止まらず、**生の推論が英語のまま `content` に流れ込む** |
| `/no_think` soft switch | 効かない |

`think: false` は「Ollama が思考を分離しなくなる」だけで、モデルの思考自体は止まらない。
対話ロボットでは**非推論モデルを選ぶこと**。

#### 採用: `qwen3:4b-instruct`

非推論版に変えたところ、思考ゼロ・初トークン 0.68s で期待どおり動いた。
日本語も自然で、ペルソナの口調（一人称・語尾）も守れる。

**VRAM には収まりきらない。** 4GB に対して `num_ctx=4096` で 33%、
`num_ctx=2048` で 27% が CPU にこぼれる。実測では 2048 のほうが速いのでそちらを採用。

#### 3B 級との比較（VRAM に載る vs 品質）

| | qwen3:4b-instruct | qwen2.5:3b |
|---|---|---|
| VRAM | 3.2GB / **27% が CPU** | 2.1GB / **100% GPU** |
| 第1文まで | 0.81s | **0.51s** |
| 一人称 | ボク（正しい） | 「私」になる |
| 語尾の活用 | 正しい | 「だのだ」等の誤りが再発 |
| その他 | — | **ペルソナ内の Markdown 記号をそのまま読み上げ文に混ぜる** |

速度では 3B が勝つが、**品質差が大きいので 4B-instruct を採用**。
0.81s は目標に対して十分に余裕がある。

なお 3B が Markdown を混ぜてきた件を受けて、
ペルソナから強調記号を排除し、TTS 直前に `sanitize_for_tts()` を通す対策を入れた。
モデルを変えても読み上げが壊れないようにするための保険。

#### ペルソナ側の注意

4B 級モデルは語尾の活用を間違える（「ロボットだのだ」など）。
`persona/usachan.md` に**文法規則を明示**したところ解消した。
小型モデルでは「正しい例と誤った例をセットで書く」のが効く。

## PC ⇄ CoreS3 プロトコル

WebSocket。**CoreS3 がクライアント**として `ws://<pc-ip>:8765/rabbit` に接続する（PC 側の IP 固定だけで済み、CoreS3 側の IP を知る必要がない）。

### PC → CoreS3

| フレーム | 内容 |
|---|---|
| text | `{"t":"state","v":"idle\|listening\|thinking\|speaking","emotion":"neutral\|happy\|puzzled\|surprised\|sleepy"}` |
| text | `{"t":"audio_begin","rate":24000,"ch":1,"fmt":"s16le"}` |
| binary | PCM チャンク（20ms = 960 bytes @ 24kHz mono s16） |
| text | `{"t":"audio_end"}` |
| text | `{"t":"audio_flush"}` — barge-in。バッファ即破棄 |

### CoreS3 → PC

| フレーム | 内容 |
|---|---|
| text | `{"t":"hello","fw":"0.1.0"}` |
| text | `{"t":"touch","x":..,"y":..}` |
| text | `{"t":"imu","event":"lift\|shake\|pat"}` |

### 補足
- VOICEVOX の出力は 24kHz / 16bit / mono。そのまま流して 384kbps——Wi-Fi では問題にならない
- プリバッファ 100ms 溜まってから再生開始（ジッタ吸収）
- **口パクは CoreS3 側で PCM の RMS から計算する。** PC 側で計算して送るより、再生バッファそのものを見るほうが同期が正確

## モジュール構成

```
pc/
  main.py                起動・イベントループ
  config.yaml            ウェイクワード、モデル、IP、バッファ長など
  state.py               状態機械 idle/listening/thinking/speaking
  wake.py                ウェイクワード判定・会話モード管理
  persona/
    usachan.md           ★ペルソナ本体（セリフ例をここに入れる）
  audio/
    mic.py               sounddevice 入力・リングバッファ
    vad.py               Silero VAD、発話区間切り出し
  stt/
    whisper.py           faster-whisper (tiny=ウェイク判定 / small=本命)
  llm/
    client.py            Claude API streaming、プロンプトキャッシュ
    sentence.py          ストリームの文分割・感情タグ抽出
  tts/
    voicevox.py          VOICEVOX HTTP、文単位合成
  transport/
    server.py            WebSocket サーバ

firmware/
  platformio.ini
  src/
    main.cpp             M5Unified init, WiFi, WS クライアント
    audio_out.cpp        リングバッファ → M5.Speaker
    face.cpp             state に応じた顔描画・口パク
    sensors.cpp          touch / IMU → PC
```

ペルソナは**コードに埋め込まず独立ファイル**にする。原作再現の調整はここだけを触って回す。
